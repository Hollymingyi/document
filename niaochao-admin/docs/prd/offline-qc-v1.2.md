# 离线质检 V1.2 增量

## Problem Statement

运营在离线质检日常使用中面临三个痛点：

1. **概念混淆**："历史重跑"命名无法区分"评分卡规则变更后回溯"和"任务级失败重试/换口径对比"两种不同场景，运营经常误用。
2. **缺少失败重试和对比能力**：一批录音质检失败后，无法在原任务基础上重试；评分卡规则调整后，无法在不影响原结果的情况下换口径对比评估。
3. **录音复核效率低**：复核员逐条听录音时，必须反复返回列表页切换下一条，无法在当前筛选范围内连续翻阅。任务明细也缺少音频文件名定位和导出对账能力。

## Solution

四组增量功能（C1-C4），三组纯前端、一组前后端协作：

- **C1**：将"历史重跑"更名为"评分卡规则重跑"，并在弹窗中澄清操作语义
- **C2**：新增"任务重跑"——从任务列表发起，在原任务基础上另建新任务，录音直接转移（不复制，保持相同 recordId），用户可选数据源和重跑深度
- **C3**：录音详情页新增"上一条/下一条"翻阅，跟随来源列表的筛选与排序
- **C4**：任务详情录音清单新增"音频文件名称"列和 CSV 导出功能

## User Stories

1. As 运营, I want 评分卡的"历史重跑"更名为"评分卡规则重跑"并在弹窗讲清"只重成功录音 + 只重跑规则 + 就地覆盖", so that 我清楚它与任务重跑的区别、不误用。
2. As 运营, I want 在任务列表对某任务发起"重跑"、系统另建新任务承载结果而原任务保留, so that 我能对比重跑前后而不破坏历史。
3. As 运营, I want 重跑时选数据源"仅成功/仅失败/全部", so that 既能失败重试也能整批重评。
4. As 运营, I want 重跑时选深度"完整重跑（含转写）/仅重跑规则"、并由系统按数据源给默认与约束, so that 在成本与必要性间权衡。
5. As 运营, I want 发起前看到"将重跑 N 条 / 跳过 M 条（按原因分类）"、可重跑数为 0 时禁止发起, so that 不产生无效重跑。
6. As 运营, I want 任务重跑默认不回传客户、可手动开启回传, so that 失败重试需回传时可推、常规重评不打扰客户对账。
7. As 运营, I want 重跑任务在列表带"重跑"标签、详情可一键跳回源任务, so that 对比定位高效。
8. As 复核员, I want 在录音详情用"上一条/下一条"在来源列表（当前筛选 + 排序）内连续切换、并看到"第 i / N 条", so that 逐条听录音复核时不必反复返回列表。
9. As 复核员, I want 翻到边界自动加载相邻页、到首尾时按钮置灰, so that 翻阅连贯且有明确边界。
10. As 复核员, I want 无来源上下文进入时前后翻置灰并提示从列表进入, so that 行为可预期。
11. As 运营/客户业务方, I want 任务详情录音清单展示"音频文件名称"列, so that 用熟悉的原始文件名定位录音。
12. As 运营/客户业务方, I want 把当前筛选后的任务录音清单导出为 CSV（所见即所得、不含录音本体、≤5000 行）, so that 线下对账与归档。
13. As 运营, I want 导出受"是否可导出录音清单"权限点控制, so that 数据外带可治理。

## Implementation Decisions

### 架构决策

- **录音不复制**：任务重跑只修改录音的 `taskId` 指向新任务，不创建新 QcRecord 行。recordId 保持不变，下游行为（webhook 回传、详情页、人工修正）天然兼容。
- **externalId 原样保留**：重跑后客户业务键不变，客户可通过同一 externalId 对账。
- **重跑深度起始状态按 channelMode 区分**：channelMode=1（双声道直接拆分）设 status=4 跳过角色识别，channelMode=2（单声道需识别）设 status=3 重新跑角色识别。
- **C3 导航上下文**：通过 sessionStorage 传递来源列表的筛选条件，跟随现有录音列表和任务详情的保存模式。

### 三类重跑概念辨析

| | 评分卡规则重跑 | 任务重跑 | 人工修正 |
|---|---|---|---|
| 入口 | 评分卡管理 | 任务列表「重跑」按钮 | 录音详情评分明细 |
| 范围 | 评分卡 + 时间段（仅成功） | 单个任务（可选成功/失败/全部） | 单条录音单评分项 |
| 是否重转写 | 否 | 用户选 | 否 |
| 产物 | 就地覆盖 | 录音转移归属到新任务 | 就地改命中+总分 |
| 是否回传 | 强制 | 默认否，可手动开启 | 强制 |
| recordId | 不变 | 不变 | 不变 |

### DB Schema

`qc_task` 新增列：

| 列 | 类型 | 说明 |
|---|---|---|
| rerun_source_id | BIGINT | NULL=常规任务；非NULL=重跑任务指向源任务 |
| rerun_depth | TINYINT | 1=完整重跑(含转写)，2=仅重跑规则 |
| rerun_data_source | VARCHAR(20) | success/fail/all |
| rerun_webhook | TINYINT | 0=不回传，1=回传 |
| rerun_operator | VARCHAR(64) | 发起人 |
| rerun_time | DATETIME | 发起时间 |

### API Contracts

**任务重跑：**
- `POST /qcTask/{taskId}/rerun/preview` — 预览可重跑/跳过条数，入参：`{ newTaskName, dataSource, rerunDepth, pushToCustomer }`
- `POST /qcTask/{taskId}/rerun` — 执行重跑，返回新任务 ID

**任务列表：**
- `GET /qcTask/list` — `taskType` 参数新增，值：`regular`/`rerun`，null=全部

**录音前后翻：**
- `GET /qcRecord/ids` — 返回筛选条件下的有序 recordId 列表（最多 10000）

**导出：**
- `GET /qcRecord/count` — 返回筛选条件下的总数
- `GET /qcRecord/export` — 导出当前筛选结果为 CSV（UTF-8 BOM，≤5000 行，同步），不含录音 URL 和转写文本

### 权限

- 任务重跑复用现有权限点 `qc_scorecard_rerun`
- 新增权限点 `qc_record_list_export`（是否可导出录音清单）

### 重跑逻辑

1. 校验源任务非重跑任务（禁止二级重跑链）
2. 校验无 `processingCount > 0` 的重跑子任务（禁止重复发起）
3. 创建新 QcTask（rerunSourceId 指向源任务）
4. 查询源任务中匹配数据源的录音，更新 `taskId` 为新任务 ID
5. 根据 rerunDepth 重置录音状态并清空历史评分结果
6. 引擎 Pipeline 自动捡起录音处理
7. 刷新源任务统计

### 前端交互

- 任务列表新增"任务类型"筛选（全部/常规任务/重跑任务）
- 任务列表操作列"重跑"按钮仅对非重跑任务显示
- 重跑弹窗：源任务信息（只读）、新任务名称（默认`{源任务名} · 重跑#{序号}`）、数据源单选（驱动默认深度）、重跑深度单选、范围预览、回传开关（默认关闭）
- 任务详情页重跑任务展示"重跑"标签 + 数据源/重跑深度/发起人/发起时间 + "查看源任务"链接
- 录音详情导航栏：来源提示、上一条/下一条、当前位置

## Testing Decisions

- **引擎 Pipeline 行为**：测试不同 channelMode 下"仅重跑规则"的起始状态正确性（channelMode=1 → status=4, channelMode=2 → status=3）
- **重跑防重复**：测试同一源任务已有进行中子任务时再次发起被拒绝
- **重跑防二级链**：测试对重跑任务再次发起重跑被拒绝
- **导出边界**：测试 ≤5000 行成功导出，>5000 行返回错误提示
- **导航上下文**：测试从录音列表进入和从任务详情进入均能正确识别来源

## Out of Scope

- 键盘快捷键（←/→）切换录音（PRD 标记 P1 可选）
- 录音复制模式下保留源录音 ID 实现交叉引用（已改为不复制方案）
- 重跑进度浮条（操作同步完成，无需异步进度提示）

## Further Notes

- 评分卡规则重跑的行为、字段、回传策略完全不变——仅文案变更
- 评分卡不应在生产中更换绑定客户，无需防御此场景
- 90 天音频保留期规则信任，不额外检查文件系统存在性
