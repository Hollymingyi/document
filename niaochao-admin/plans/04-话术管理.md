# 鸟巢侧改造 · 话术管理（MVP）

## 四、话术管理（新增 · MVP）

> 本期是话术能力的最小落地版本。仅承载"放话术 + 是否转人工"两个核心动作，用于支撑 AI外呼 与人机协作任务的话术产品选项。

### 4.1 入口与定位

- **入口**：智能外呼 → 话术管理（一级菜单）
- **定位**：话术产品的最小必备载体；本期不做对话流编排、变量解析、多分支等高级能力，相关能力放后续版本
- **覆盖任务类型**：
  - **AI外呼**：可选 `不转接` 或 `转接` 类话术
  - **人机协作**：**必须**选 `转接` 类话术（用于触发"转人工坐席"动作）

### 4.3 新建 / 编辑话术

| 字段       | 是否必填 | 规则                                                                        |
| -------- | ---- | ------------------------------------------------------------------------- |
| **关联客户** | ✅    | **下拉单选**；选项 = 当前用户可见的所有客户。**创建后不可修改**（避免话术归属与统计口径混乱）                      |
| 话术名称     | ✅    | **客户内唯一**（同一客户下不可重名，跨客户允许重名），最长 50 字                                      |
| 语料       | ✅    | 多行文本，最多 1000 字；用于 TTS 备稿 / 文案审计 / 客户参考                                    |
| 音频文件     | ✅    | **仅支持 `.wav`** 格式，单文件 ≤ 10MB；上传成功后展示文件名 + 大小 + 时长 + 试听播放器                |
| 转接类型     | ✅    | 单选：<br/>· `不转接`：音频播放完毕直接挂断<br/>· `转接`：音频播放完毕后**转人工坐席**接通；坐席接通失败则按系统超时策略挂断 |
| 启用状态     | ✅    | 开关；禁用后新建任务的"话术"下拉项不再展示该话术（已引用任务不受影响）                                      |
| 备注       | ❌    | 选填，最多 200 字                                                               |

**编辑限制（仅当 `关联任务数 > 0` 时生效；`= 0` 时所有字段自由编辑）**：

| 字段 | 是否允许修改 | 修改后行为 |
|------|------------|-----------|
| 语料 | ✅ 可改 | **实时生效**：所有引用该话术的任务立即按新语料执行（仅影响后续播放/呼叫） |
| 音频文件 | ✅ 可改 | **实时生效**：上传新音频后，所有引用该话术的任务在下一次拨打时使用新音频；进行中的呼叫不打断 |
| 备注 | ✅ 可改 | 即时生效 |
| 启用状态 | ✅ 可改 | 仅影响新建任务的下拉可见性，详见 §4.5 |
| 话术名称 | ❌ 不可改 | 避免上下游 UI / 报表 / 日志中既有引用名错位 |
| 转接类型 | ❌ 不可改 | 改动会破坏既有任务执行行为：`转接 → 不转接` 让人机协作任务失去转人工链路；`不转接 → 转接` 会让 AI 外呼意外触发人工坐席 |
| **关联客户** | ❌ **始终不可改**（不论关联任务数） | 跨客户迁移会导致历史任务数据归属混乱；如需将话术归到另一客户，请在新客户下重新建一份 |

> **活引用模型（Live Reference）**：任务侧通过 `script_id` 引用话术记录，**不做内容快照**。话术内容变更后，所有引用该话术的任务（含已结束任务被重启、进行中任务的下次拨打、待启动任务）都会实时拿到新内容。该模型简化运营（错字修正、音频迭代无需新建话术），代价是**音频/语料变更对运营是一次"全量影响"动作**，需在编辑抽屉显著提示。

> **删除限制**：仅 `关联任务数 = 0` 时允许删除（避免任务侧 `script_id` 失效）；列表"删除"按钮在已关联时置灰，hover 提示原因。

### 4.4 话术与任务模板的联动

任务模板"话术"字段下拉项由 **3 个条件共同过滤**：

1. **客户匹配**：仅展示 `话术.关联客户 = 模板.所选客户` 的话术（话术与任务严格按客户隔离）
2. **启用状态**：仅展示 `启用中` 的话术
3. **转接类型匹配任务类型**：

| 任务类型 | 转接类型过滤 | 空数据态提示 |
|---------|-------------|-------------|
| AI外呼 | `转接` / `不转接` 均可（不过滤） | `该客户当前无可用话术，请前往「智能外呼 → 话术管理」为该客户创建话术` |
| 人机协作 | 仅 `转接` | `该客户当前无可用的转接类话术，请前往「智能外呼 → 话术管理」为该客户创建转接类话术` |

> 模板未选客户前，"话术"字段灰化禁用；切换模板的"所选客户"会清空话术取值并重新加载下拉。
> 该联动取代了原"话术产品"模块的对应入口，本期 PRD 内引用"话术 / 话术产品"时统一指向本章。

### 4.5 启用 / 禁用规则

- **禁用**仅控制"**新建任务**的话术下拉项可见性"；不影响已引用任务的执行
- 已引用任务在执行时仍按当前话术配置加载（包括禁用期间的最新语料 / 音频修改，与 §4.3 活引用模型一致）
- **二次确认**：当 `关联任务数 > 0` 时弹出 `禁用后该话术将不再出现在新建任务的下拉项；已引用该话术的任务继续可执行，话术内容（语料 / 音频）的最新修改对其实时生效。`
- **启用**：直接 toggle，不需要二次确认

### 4.6 话术执行流程

> **范围**：本节描述**接通之后**的话术执行链路。接通前的拨号 / 振铃 / 占线 / 路由等待 / 频次限制等通用规则不在本节范围（由外呼线路 / 任务调度侧统一处理）。

> **接通后起播时机（规避运营商 / 线路前置音重叠）** 🆕
> **背景（为什么需要这个判断）**：线路供应商在接通后会先播放一段运营商前置音（如"来电已启用隐私保护"），**该提示音由运营商 / 线路侧控制，长度不固定、各线路供应商也不一样**。关键在于——**前置音播放期间，主被叫双方的语音是互相听不到的**：此时若按"收到接通即起播"播放话术，话术开头会与前置音重叠，而**重叠的这段客户完全听不到**，等于话术被截头、客户一上来就漏听关键信息（甚至误以为是空白来电而直接挂断），转化与体验都受损。因此必须等前置音结束、通道空闲后再起播。
> **处理**：收到"接通"信令后**不立即起播**，先对下行通道做 **VAD（语音活动检测）**；当检测到**持续 ≥ 1 秒静音**（判定前置音结束、通道空闲）时再开始播放话术音频。无前置音的线路会在接通后迅速判定静音并起播，自然兼容。
> **兜底**：设最大等待时长，若超时仍未检测到静音（线路异常 / 持续噪声等）则到上限后直接起播，避免无限等待。
> **全局参数**（系统级，非话术 / 非线路级配置）：
> - `playback_silence_gate_ms`：静音判定持续时长，默认 **1000ms**（即 1 秒）
> - `playback_max_wait_ms`：起播最大等待（兜底）时长，默认 **5000ms**
> - `vad_silence_threshold`：静音能量阈值（工程参数，运维可调）。单帧能量 ≤ 该值判为"静音帧"，否则为"活动帧"（前置音 / 话音 / 噪声）。
>
> **参数使用逻辑与起播判定流程**：
> 1. 收到"接通"信令且媒体通道建立后记起始时刻 `t0`，**不起播**，开始对接收到的下行音频流逐帧做能量检测。
> 2. 用 `vad_silence_threshold` 判定每帧是"静音帧"还是"活动帧"。
> 3. 累计**连续**静音时长：一旦遇到活动帧即**清零重新计**；当连续静音时长 ≥ `playback_silence_gate_ms`（默认 1000ms）→ 判定"前置音结束、通道空闲"，**立即起播**。
> 4. **兜底**：自 `t0` 起独立计时，若达到 `playback_max_wait_ms`（默认 5000ms）仍未满足第 3 步（如线路持续噪声 / 始终无明显静音）→ 到点**强制起播**，不再等待。
> 5. **起播触发 = 第 3 步（静音达标）与第 4 步（兜底超时）先到者生效**；起播后进入 §4.6.1 / §4.6.2 的播放与转接链路。
>
> ```text
> 接通(t0) ──► VAD 逐帧检测下行音频（能量 ≤ vad_silence_threshold → 静音帧）
>               │   遇活动帧：连续静音累计清零、重新计
>               ├─ 连续静音 ≥ playback_silence_gate_ms (默认 1s) ──► 起播
>               └─ 自 t0 计时 ≥ playback_max_wait_ms (默认 5s) ───► 强制起播（兜底）
> ```
>
> **边界与代价**：
> - **无前置音线路**：接通后通道即静音，约 1 个 `playback_silence_gate_ms`（默认 1s）后起播，即每通最小约 1s 等待，属可接受代价。
> - **前置音超长（> `playback_max_wait_ms`）**：极少数情况在 5s 上限被强制起播时前置音可能尚未结束，仍有少量重叠；可上调 `playback_max_wait_ms` 缓解。
> - **前置音内部长停顿（≥ `playback_silence_gate_ms`）**：可能被误判为结束而提前起播；默认 1s 通常长于前置音内部停顿，必要时运维微调 `playback_silence_gate_ms` / `vad_silence_threshold`。
>
> 该时机仅作用于"接通 → 起播"之间，不改变后续 §4.6.1 / §4.6.2 的播放与转接逻辑。

#### 4.6.1 不转接类执行流程

```text
接通
  │
  ▼
等待前置音结束（VAD：持续 1s 静音，或达最大等待上限）
  │
  ▼
开始播放音频
  │
  ├──► 音频播完 ──────────► 系统挂断
  │                              │
  │                              ▼
  │                       呼叫结果 = 接通（音频完整播完）
  │
  └──► 客户中途挂断 ────────► 通话结束
                                 │
                                 ▼
                          呼叫结果 = 接通（音频未播完 · 客户挂断）
```

#### 4.6.2 转接类执行流程

```text
接通
  │
  ▼
等待前置音结束（VAD：持续 1s 静音，或达最大等待上限）
  │
  ▼
开始播放音频
  │
  ├──► 客户中途挂断 ──────────► 呼叫结果 = 接通（音频未播完 · 客户挂断）
  │                              不触发转人工
  │
  └──► 音频播完 ──────────► 触发转人工请求
                                 │
                                 ▼
                          坐席组内分配空闲坐席（详见 §4.6.3）
                                 │
            ┌────────────────────┼────────────────────┐
            ▼                    ▼                    ▼
      坐席接通成功            坐席接通超时          无空闲坐席
            │                    │                    │
            ▼                    ▼                    ▼
       坐席跟进通话          系统挂断              系统挂断
            │                    │                    │
   （客户或坐席挂断）            ▼                    ▼
            │            呼叫结果 = 接通 +      呼叫结果 = 接通 +
            ▼              转人工失败             转人工失败
      呼叫结果 = 接通 +    （坐席接通超时）        （无可用坐席）
      转人工成功
```

#### 4.6.3 转接的坐席选择规则

| 项         | 规则                                                    |
| --------- | ----------------------------------------------------- |
| **候选范围**  | 该任务模板绑定坐席组（§二）下，账号级 + 坐席组级**均为启用**且**当前空闲**（不在通话中）的坐席 |
| **选择策略**  | 按"最近一次结束通话时间最早"优先派单（最长空闲优先），实现组内负载均衡                  |
| **接通超时**  | 转接发起后，**30 秒**内无坐席接通即超时；标记"转人工失败-坐席超时"后系统挂断           |
| **失败兜底**  | 系统直接挂断；**不留言、不自动重试**；名单流转状态保持当前态，可由组长在工作台手动派单 / 重发    |
| **坐席不在线** | 坐席登录但状态非"空闲"（如示忙 / 小休）不进入候选                           |
| **跨组禁止**  | 不允许跨坐席组分配，与 §6.2 流转状态机 / §2.6 组长权限保持一致                |

#### 4.6.4 异常分支与双维度状态机映射

接通后阶段产生的所有结果**直接映射到名单的双维度状态字段**（详见 §6.2.2 / §6.2.3 / §6.2.7）：

| 场景             | 触发条件                                  | `transfer_status` | `last_failure_reason` | 后续动作                                                                         |
| -------------- | ------------------------------------- | ----------------- | --------------------- | ---------------------------------------------------------------------------- |
| 音频完整播完（不转接类话术） | 播完后系统挂断                               | `not_triggered`   | NULL（不转接类无失败概念）       | 不转人工，名单按"已结束"处理（不转接类不进入双维度状态机的失败重试链路）                                        |
| 客户音频中途挂断       | 接通后客户挂断（音频未播完）                        | `not_triggered`   | `customer_mid_hangup` | **不自动重试**：中途挂断视为客户负向信号，自动重拨易引发反感与投诉；如需再拨由运营在工作台手动添加呼叫（需 §6.2.7 将该原因移出自动重试链路） |
| 客户听完话术明确拒绝转人工  | 完整话术 + 客户表态拒绝（⚠ 本期无意图识别，无法自动判定，见表下说明） | `not_triggered`   | `customer_declined`   | **不自动重试**（§6.2.8.1 添加呼叫也禁止）                                                  |
| 转人工成功          | 转接发起 → 坐席接听 → 通话结束                    | `succeeded`       | NULL                  | 名单 `flow_status = assigned`；进入跟进流程                                           |
| 转人工失败-坐席超时     | 转接 30 秒内无坐席接通                         | `failed`          | `agent_no_pickup`     | **不重试**（运营手动添加呼叫或归档；详见 §6.2.7 Tier 3）                                        |
| 转人工失败-无可用坐席    | 转接时全组无空闲启用坐席                          | `failed`          | `no_idle_agent`       | **不重试**（运营手动添加呼叫或归档；详见 §6.2.7 Tier 3）                                        |
| 转人工失败-网络异常     | 转接通道异常 / 坐席接通后立刻断线                    | `failed`          | `network_error`       | **不重试**（运营手动添加呼叫或归档；详见 §6.2.7 Tier 3）                                        |

> 拨号 / 振铃阶段的失败原因（占线 / 无人接 / 拒接 / 空号 / 反诈拦截 / 关机）按 §6.2.7 Tier 1 枚举写入 `last_failure_reason`；不再独立维护"呼叫结果"字段。
> 重试调度由**补呼策略**（`PRD-任务模块改造.md §五`：补呼次数 + 每轮间隔 + 触发条件）+ `next_retry_at` 驱动；具体由当前补呼轮的"间隔时间"决定 `next_retry_at`，由当前补呼轮的"触发条件"过滤 `last_failure_reason` 是否进入下一轮拨号循环。
>
> **关于 `customer_declined`（本期说明）**：本期**未做意图识别 / ASR 语义判定**，系统无法自动感知"客户听完后表态拒绝转人工"。按 §4.6.2 流程，转接类话术"音频播完"一律进入"触发转人工请求"分支，**不存在自动判定"客户拒绝"的路径**。该枚举**保留供后续版本（引入意图识别后）或人工标记**使用，本期不会被自动写入。
> **关于 `customer_mid_hangup`（本期口径）**：客户中途挂断**不自动重试**（避免反感投诉）；与 §6.2.7 的重试分层需保持一致——该原因应归入"不进入自动补呼循环"的档位，仅允许运营手动添加呼叫。

#### 4.6.5 客户按键 / DTMF

- **MVP 阶段不解析**：客户在播放期间的任何按键不触发分支，按钮事件忽略
- 后续版本若引入 IVR / 按键导航，需扩展话术结构（节点树）；本期保持单段语料 + 单分支（转 / 不转）

### 4.7 音频文件规范

| 项 | 规则 |
|----|------|
| 格式 | **仅支持 `.wav`**；上传 `.mp3` 等其他格式将在前端拦截并提示"仅支持 .wav 格式" |
